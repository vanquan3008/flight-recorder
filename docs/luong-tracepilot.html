Luồng hoạt động của TracePilot

Một ứng dụng Go gồm API quản trị, bộ thu OTLP và các worker nền, nói chuyện với một PostgreSQL riêng; console React là ứng dụng riêng phía trước. Sáu sơ đồ dưới đây vẽ đúng theo code hiện tại ở nhánh feat/runtime-hardening, đối chiếu với docs/FLOW.md.

1Các thành phần và dữ liệu chảy qua đâu

Telemetry đi một chiều vào PostgreSQL qua pipeline; mọi thứ khác đọc và ghi cùng cơ sở dữ liệu đó.

  • Repo không có Compose. PostgreSQL là dịch vụ ngoài; backend chạy bằng go run hoặc image build từ backend/Dockerfile (distroless, user nonroot).
  • Bộ thu OTLP và API dùng chung một JWT secret: ingest token và access token cùng được ký bằng nó.

2Một request OTLP đi qua những gì

Mỗi cổng kiểm đứng trước bước tốn tài nguyên hơn; request chỉ được ACK sau khi dữ liệu đã commit.

  • Mỗi request OTLP tốn một truy vấn kiểm ingest token. Token không được cache nên thu hồi có hiệu lực ngay.
  • Ngân sách byte của hàng đợi là ước lượng, không phải giới hạn RSS vì gRPC giải mã trước khi vào hàng đợi.

3Khởi động và tắt có thứ tự

Server kiểm schema chứ không tự migrate; khi tắt, listener dừng trước rồi mới drain pipeline.

  • Chạy tracepilot migrate up trước serve. Nếu schema sai version hoặc dirty, server thoát ngay và /health/ready báo not ready.

4Một request API được kiểm quyền thế nào

Quyền được khai báo trong bảng route; handler không tự kiểm.

  • Rate limit chia ba nhóm (query, auth, replay) và tính theo từng tiến trình. Chạy nhiều replica thì đặt thêm giới hạn ở reverse proxy.

5Vòng đời incident

Chỉ một chuyển trạng thái xảy ra tự động: RESOLVED quay lại OPEN khi lỗi tái diễn.

  • Incident được đánh dấu mở hoặc mở lại sẽ phát webhook incident.opened; bản mở lại mang reopened: true.
  • RCA chỉ xếp hạng giả thuyết theo độ tin cậy từ evidence và quan hệ phụ thuộc, không phải kết luận.

6Webhook qua outbox

Việc gửi được xếp hàng trong cùng transaction với incident nên không mất khi tiến trình chết giữa chừng.

7Giới hạn đã biết

Những điều sơ đồ trên không đảm bảo.

  • Chạy một replica: rate limiter và sổ chặn xác thực nằm trong bộ nhớ; detection và retention chạy ở mọi replica.
  • Pool kết nối mặc định là 200, nhiều hơn mặc định 100 của PostgreSQL. Cần chỉnh theo server thật.
  • Chưa đo tải, SLO, sao lưu và phục hồi; chưa có SSO, MFA, xóa project hoặc environment.
  • Unit test và integration test qua không phải chứng nhận production.
