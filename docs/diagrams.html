3. Đăng ký, đăng nhập, refresh

Access token (15 phút) nằm trong bộ nhớ; refresh token ngẫu nhiên nằm trong cookie HttpOnly và đổi mới mỗi lần dùng.

sequenceDiagram
  autonumber
  participant C as Console
  participant A as API
  participant D as PostgreSQL
  C->>A: POST /auth/login
  A->>A: Rate limit theo IP và 10 lần mỗi email
  A->>D: Tìm tài khoản theo email
  A->>A: Kiểm mật khẩu - email lạ vẫn tốn cùng thời gian
  alt sai hoặc bị khóa
    A-->>C: 401 INVALID_CREDENTIALS
  else đúng
    A->>D: Tạo phiên refresh - chỉ lưu SHA-256
    A-->>C: Cookie tp_refresh + access token 15 phút + danh sách project
  end
  Note over C,A: Gọi API với Bearer access token
  C->>A: Request
  A-->>C: 401 TOKEN_EXPIRED
  C->>A: POST /auth/refresh kèm header X-TracePilot-Refresh
  A->>D: Đổi token cũ lấy token mới trong một câu lệnh
  alt token hợp lệ và tài khoản còn hoạt động
    A-->>C: Cookie mới + access token mới
    C->>A: Gửi lại request
  else token lạ, đã dùng, hết hạn
    A-->>C: 401 - xóa cookie, về trang đăng nhập
  end

6. Vòng đời incident

Cùng fingerprint thì gộp thành một incident; mỗi lần đổi trạng thái đều ghi lịch sử.

stateDiagram-v2
  [*] --> OPEN: Lỗi mới hoặc detection phát hiện
  OPEN --> OPEN: Occurrence mới - tăng bộ đếm
  OPEN --> INVESTIGATING: Người dùng nhận xử lý
  INVESTIGATING --> RESOLVED: Người dùng đóng
  OPEN --> RESOLVED: Người dùng đóng
  OPEN --> IGNORED: Người dùng bỏ qua
  INVESTIGATING --> IGNORED: Người dùng bỏ qua
  RESOLVED --> OPEN: Occurrence mới hơn lúc resolve
trong cửa sổ 1 giờ - actor system
  IGNORED --> OPEN: Người dùng mở lại
  RESOLVED --> [*]: Retention sau 90 ngày yên
  IGNORED --> [*]: Retention sau 90 ngày yên
  note right of OPEN
    Mở hoặc mở lại thì xếp
    webhook vào outbox
  end note

8. Vòng đời ingest token

Chuỗi JWT chỉ hiện một lần, ký bằng secret riêng; thu hồi có hiệu lực ngay nhờ bộ đệm tự xóa khi bị thu hồi.

sequenceDiagram
  autonumber
  participant O as Owner
  participant A as API
  participant C as Token Cache
  participant D as PostgreSQL
  participant S as Ứng dụng gửi telemetry
  participant R as Bộ thu OTLP
  O->>A: POST /projects/{id}/ingest-tokens
  A->>D: Ghi metadata + audit (ký bằng INGEST_JWT_SECRET)
  A-->>O: JWT hiện một lần
  O->>S: Cấu hình OTEL_EXPORTER_OTLP_HEADERS
  S->>R: Export kèm Bearer token
  R->>C: Tra cứu bộ đệm in-memory (TTL 30s)
  alt Cache miss
    C->>D: Tra DB rồi lưu vào bộ đệm
  end
  R-->>S: ACK sau commit
  O->>A: DELETE /ingest-tokens/{id}
  A->>D: revoked_at = now + audit
  A->>C: Invalidate(tokenID) xóa cache ngay lập tức
  S->>R: Export tiếp
  R->>C: Cache miss -> tra DB
  R-->>S: 401 - token đã bị thu hồi

10. Partition và retention

Bảo trì partition mỗi giờ; retention chạy theo chu kỳ, mỗi nhóm một max_age (0s là giữ mãi).

  subgraph Ret["Retention - mỗi RETENTION_CHECK_INTERVAL"]

  K["Không bao giờ xóa:

11. Telemetry streaming thời gian thực (SSE)

Stream log mới và cảnh báo sự cố trực tiếp tới console qua Server-Sent Events, tối đa 256 kết nối đồng thời và không chiếm concurrency slot.

sequenceDiagram
  autonumber
  actor User as Console (Live Tail)
  participant API as HTTP API (:8080)
  participant Hub as StreamHub (In-Memory)
  participant Pipe as Ingestion Pipeline
  participant DB as PostgreSQL

  User->>API: GET /api/v1/live/stream (Bearer token)
  API->>API: Xác thực scope read & resolve env
  API->>Hub: Đăng ký subscriber (project, env)
  Hub-->>API: Từ chối nếu đã đủ 256 subscriber
  API-->>User: 200 OK (text/event-stream, event: connected)
  loop Ingest & Commit
    Pipe->>DB: Commit batch telemetry
    DB-->>Pipe: Transaction committed
    Pipe->>Hub: BroadcastEvents(batch)
    Hub->>API: Non-blocking dispatch qua channel
    API-->>User: data: {"type":"log", "payload":{...}}\n\n
  end
