1. Tổng quan hệ thống

Một ứng dụng Go phục vụ API và OTLP; PostgreSQL quản trị/trace/metric/incident, ClickHouse bắt buộc lưu raw log. cmd nối dependency; application điều phối qua interface nhỏ; domain giữ quy tắc thuần. Console ghép route ở app, feature dùng context từ shared/session và không phụ thuộc ngược vào app. Phạm vi MVP và roadmap nằm trong README.

2. Khởi động và tắt

Database-first: schema SQL có version là nguồn cho sqlc và runtime. PostgreSQL kiểm trạng thái/severity incident và event webhook hợp lệ kể cả khi import hoặc ghi SQL trực tiếp; dữ liệu cũ sai quy tắc làm migration constraint thất bại, không bị tự sửa/xóa.

flowchart LR
  Schema["Migration SQL mới"] --> Queries["Cập nhật named query"]
  Schema --> Generate["sqlc generate + vet"]
  Queries --> Generate
  Generate --> Adapter["Cập nhật storage Go"]
  Adapter --> Verify["Integration trên DB dùng một lần
cài mới, chạy lại, dữ liệu hợp lệ và vi phạm"]
  Schema --> Embedded["SQL nhúng trong binary"]

PG và CH có entry point quản lý riêng, mỗi bên chỉ nạp cấu hình của kho đó từ backend/.env; thiếu hoặc sai cấu hình kho kia không chặn lệnh riêng. SQL, version, journal và cờ auto độc lập. Auto-migrate gọi trực tiếp runner của từng kho. Helper chung chỉ giữ phần CLI và tính status thuần; hai storage adapter không import nhau. migrate all là lệnh tiện ích gọi lần lượt PG rồi CH, không giữ journal/version chung, rồi dùng lại luồng mở client/readiness của runtime với credential database; lỗi thì chặn khởi động, không tự rollback. status/version chỉ đọc và không chờ khóa mutation. serve chạy migration theo DATABASE_AUTO_MIGRATE và CLICKHOUSE_AUTO_MIGRATE (mặc định false) trước listener/worker. Runner PG tự giữ advisory lock, kể cả tạo journal mới. CH kiểm layout trước khi đổi TTL và kiểm schema/cột trước khi ghi clean; DDL không idempotent cần một updater.

3. Đăng ký, đăng nhập, refresh

tracepilot seed chỉ tạo super admin development, không tạo project, environment, membership hay telemetry mẫu; chạy lại giữ nguyên tài khoản và dữ liệu đã có. Sau khi đăng nhập, người dùng tạo project trong console.

application/session xác minh credential và đổi mật khẩu qua storage port. HTTP giữ rate limit, JWT, cookie và response contract. Đổi mật khẩu thu hồi phiên/token trong transaction rồi xóa identity cache và trả JWT mới. Access token (15 phút) nằm trong bộ nhớ; refresh token ngẫu nhiên nằm trong cookie HttpOnly và đổi mới mỗi lần dùng.

7. Phát hiện bất thường và RCA

Worker cũ tổng hợp tối đa 64 phút dirty mỗi scope (deadline 5 giây), rồi detection chạy nền. Query dùng summary clean và đọc span gốc cho phần chưa tổng hợp; dữ liệu đến muộn đánh dấu dirty lại. Performance giữ timestamp và latency từng request để tính p95/p99 chính xác. RCA tính khi xem incident.

8. Vòng đời ingest token

Chuỗi JWT chỉ hiện một lần, ký bằng secret riêng. Thu hồi xóa cache của tiến trình xử lý và shared entry; replica khác có thể còn cache local tới khi hết TTL.

  R->>C: Cache miss -> tra DB
  R-->>S: 401 - token đã bị thu hồi

11. Telemetry streaming (SSE) và điều tra trace

Stream tối đa 256 kết nối/tiến trình, không chiếm query slot; kết thúc theo JWT, kiểm quyền mỗi 15 giây với deadline 2 giây và giới hạn ghi từng frame 5 giây. Console giữ scope trên URL, dùng cùng API client cho REST/SSE, lọc và khử trùng 100 event live. Waterfall render hữu hạn ngay từ đầu, inspector nằm ngoài các dòng. Bảng tải thêm chủ động tối đa 20 trang; drill-down giữ nguyên from/to.

Trace detail ưu tiên operation và trạng thái request, gom self-time theo service; service map mở theo yêu cầu. Inspector nằm bên phải trên desktop, xếp dưới trên mobile và có tab hỗ trợ bàn phím. Log nằm dưới timeline, từng dòng mở khi cần; bộ lọc cục bộ chỉ tìm trong dữ liệu đã tải.

sequenceDiagram
  autonumber
  actor User as Console (Live Tail)
  participant API as HTTP API (:8080)
  participant Hub as application/live.Hub (In-Memory)
  participant Pipe as Ingestion Pipeline
  participant DB as PostgreSQL
  participant CH as ClickHouse (raw logs)

  User->>API: GET /api/v1/live/stream (JWT, X-Project-ID, X-Environment)
  API->>API: Xác thực scope read & resolve env
  API->>Hub: Đăng ký subscriber (project, env)
  Hub-->>API: Từ chối nếu đã đủ 256 subscriber
  API-->>User: 200 OK (text/event-stream, event: connected)
  Note over User,API: Stream hết hạn theo JWT; console reconnect bằng token hiện tại hoặc refresh khi TOKEN_EXPIRED
  opt Mỗi 15 giây
    API->>DB: Kiểm tài khoản và membership trực tiếp, deadline 2 giây
    DB-->>API: Còn quyền hoặc từ chối/lỗi
    Note over User,API: Hết quyền hoặc lỗi kiểm tra thì đóng stream
  end
  loop Ingest & Persist
    opt Batch có raw log
      Pipe->>CH: Ghi batch raw log, chờ flush
      CH-->>Pipe: Xác nhận ghi
    end
    Pipe->>DB: Commit trace và envelope lỗi log + incident/outbox (nếu có)
    DB-->>Pipe: Transaction cần thiết đã commit
    Pipe->>Hub: BroadcastEvents(batch)
    Hub->>API: Non-blocking dispatch qua channel
    API-->>User: data: {"type":"log", "payload":{...}}\n\n
  end
